# 实施与验收

## 架构
`EncoCore` 负责帧编解码和状态；`EncoBluetooth` 负责原生 SDP/RFCOMM；`encoctl` 提供有限时长的诊断与可恢复实测；`EncoMenu` 提供菜单栏 UI。核心不依赖蓝牙，可使用录制回包离线验证。

只连接已经与 Mac 建立连接的 X3；发现服务采用 UUID，不硬编码 channel。仅关闭本应用的 RFCOMM channel，不断开系统音频连接。显示值来自设备回包，写入成功需要 ACK 和查询读回确认；失联、超时和未知值独立显示。

## 顺序
1. 已连接设备与 SDP 缓存只读检查。
2. 原生 vendor RFCOMM 只读抓包、型号确认、电量/ANC 状态解析。
3. 记录原始 ANC 位图，逐项测试关闭/通透/降噪，查询确认，恢复原值并核验。
4. 菜单栏应用、重连、数据新鲜度、启动包和本机启动验证。
5. 依据实际能力与回包扩展降噪档位、EQ、耳机空间音效、双设备状态；不明确的写操作保持关闭。

## 原则
- 源码编译和离线测试不能替代实机成功；协议 ACK 不能替代感知效果确认。
- 模式名称先依据 X3 配置，实机回读验证数值，听感语义另作标记。
- 充电盒休眠可能不报告电量，界面显示未知及更新时间，不用历史值冒充实时数据。
- 耳机自身的空间音效不等同于 macOS/Apple 动态头部追踪整合。
- iCloud 配对、查找网络、Apple 自动切换和系统 AirPods 弹窗不在可承诺能力范围内。
